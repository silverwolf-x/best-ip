# Agent Note: 离线快照拼装层的三处转义缺口

Status: implemented

## Problem

离线快照（`.mhtml` / `.html`）的拼装层 `frontend-next/app/snapshot.js` 里有三处转义缺口，都是"看得见的错"或"迟早会响的错"：

1. **title 被转义两次。** `buildSummary()` 里 `sourceTag` 先 `escapeHtml(realSource)` 一次，而 `buildSnapshotDocument()` 写 `<title>${escapeHtml(summary.title)}</title>`（`app/snapshot.js:207`）时又对整串转一次。来源名含 `&` 时标题就会写成 `&amp;amp;`——用户在**文件管理器/浏览器标签页**上直接看到坏标题（本轮给标题加"来源 + 生成时间"正是为了让归档/转发的快照自证来源，所以这条路径会被真实用到）。
2. **`escapeHtml()` 漏单引号 `'`。** 原先只转 `&` `<` `>` `"`。产物会被转发、被别的工具再加工，下游任何用单引号写属性的地方都会被我们送去的裸 `'` 打破。
3. **统计数字与视图数字裸拼进 HTML。** `statsHtml` / `stateHtml` / `countHtml` 里的 `total` / `success` / `partial` / `failed` / `shown` 直接以 `${…}` 插进标记，只靠一条"上游 `main.js` 这几个字段一定是 number"的类型纪律兜着——那条纪律没有任何地方强制它（没有类型系统、没有断言），也不该由拼装层替上游背。

## Decision

三条不变量，全部落在 `app/snapshot.js`：

- **title 里存未转义原文，只在写 `<title>` 那一步统一转义一次。** `buildSummary()` 返回的 `title` 由 `${sourceTag}节点质量榜 · 离线快照 · ${state.generatedAt}` 组成，其中每个字段都是原文（`sourceTag` 里的来源不再预先转义，见 `app/snapshot.js:260`；`generatedAt` 本来就是原文）。唯一的转义点是 `buildSnapshotDocument()` 的 `<title>${escapeHtml(summary.title)}</title>`（`app/snapshot.js:207`）。摘要里的「来源：<b>…</b>」是另一处出口，它在 `sourceHtml` 里各转一次（`app/snapshot.js:262`），与标题互不叠加。
- **`escapeHtml()` 补齐四种字符**：`&` `<` `>` `"` `'`（单引号转成 `&#39;`，`app/snapshot.js:135-142`）。替换顺序有硬要求：`&` 必须第一个替换，否则后面替换出来的 `&#39;` 之类的实体会被自己的 `&` 规则再转一遍，又变成双转义。文本与属性共用这一套。
- **拼装层自己保证"拼进去的东西不会是标记"**：所有会进 HTML 的值一律过 `escapeHtml()`，不看上游声称它是什么类型——数字字段也照转（`<b>${escapeHtml(total)}</b>` 等，`app/snapshot.js:266-268`）。拼装层能自己保证的只有这一条，不变量"上游一定是 number"没有任何地方能保证它。

同一批次里同类性质的一处：`exportSnapshot()` 原来的 `location.href` 是裸读全局（在非窗口环境里是**未声明的标识符**，读它就是 `ReferenceError`），现在走 `currentDocumentUrl()`，`globalThis.location?.href || globalThis.document?.baseURI || 报错`，并去掉 `#` 与 `?` 之后作为部件 `Content-Location` 的来源。

## Alternatives considered

**只在调用方保证输入干净（上游先把来源、筛选词转义好再传进拼装层）。** 最强理由：转义属于"这串数据从哪来、有没有被处理过"的知识，让最清楚来源的那一层一次性处理完，可以避免同一份值在不同出口被转不同次数；拼装层则保持"只做拼接"的简单形状，也不必在每个插值点上判断要不要转。否定原因：那是没有强制力的纪律——本次缺陷正是这么来的（上游把"已经转义过的"当原文传下去，拼装层再转一次）。更要命的是它**不可判定**：拼装层拿到一个字符串时，没有任何办法区分它是原文还是已被转义的原文，所以"恰好转一次"这条性质只能锚在唯一的写出点上，才可能被代码保证、被测试断言。

**只补单引号，title 的双转义留着（把 `&amp;amp;` 当可接受的显示瑕疵）。** 最强理由：改动最小、风险最低——双转义只在来源名含 `&` 时才现形，而节点来源名里 `&` 不常见；补单引号是纯加法，不改变任何已有输出的形状。否定原因：坏标题是用户**唯一可见**的那一层（文件管理器与标签页），而"来源"正是快照要被转发/归档时最先被看到的信息；而且修它的方法恰好就是把"转义点唯一化"这件事显式写下来，顺手删掉"上游到底转没转过"这个歧义——比只补一个字符更能防住下一处同类缺陷。

**数字字段不转义，继续由上游的类型纪律保证它们是 number。** 最强理由：拼装层不是数据校验层；数字本来不含任何需要转义的字符，给它们套 `escapeHtml()` 会让代码读起来像在防一个不存在的攻击面，也让"为什么数字要转义"永远没有一个显然的答案。否定原因：那份纪律没有任何地方强制它（`main.js` 只是"目前"传的是数字），而拼装层的代价只有一次函数调用；快照是会离开站点的文件，拼装层自己守住"不会是标记"这条性质比信任上游便宜得多——上游哪天把 `String(count)` 或格式化后的字符串塞进来，这里也不会破。

## Consequences

收益：

- 来源含 `&` / `<` / `'` 时标题与摘要都正确（`AT&T & <op> 'x'` 只被转义一次），用户在文件列表里看到的是原文，不是 `&amp;amp;`。
- 转义点唯一（写 `<title>` 的那一步），"该不该再转"的歧义消失：将来新增一个进 title 的字段只要放原文即可。
- 数字/视图字段任意输入都不会变成标记：上游把 `"2<script>"`、`"<b>1</b>"`、`"x&y"` 塞进 `total` / `shown` / `success`，产物里也只出现实体。
- 单引号被转义之后，产物可被下游用单引号写属性的工具安全再加工；`location` 也不再以裸标识符出现（非窗口环境里不再 `ReferenceError`）。

代价：

- `title` 的语义变了：字段里存的是**未转义原文**。谁把 `summary.title` 直接塞进 HTML 就会重新引入注入面——这条不变量只在 `buildSnapshotDocument()` 内部成立（它是唯一的写出点，但没有任何类型能强制它）。同一个 `title` 还被用作 MHTML 的 `Subject`（`serializeSnapshot()` 的 `subject`），那里本来就该是原文，所以方向是对的。
- `escapeHtml()` 现在改变更多字节：文本里的 `'` 会变成 `&#39;`（文本里本来合法），产物对这些字符不再逐字等于输入。"转发之后仍然安全"优先于"逐字一致"。
- 拼装层多一层防御不等于上游可以放松：`main.js` 的类型纪律仍然存在（只是不再被依赖），也没有任何断言在检查上游真的传了数字。
- `escapeHtml()` 仍然只处理五种字符，不是通用 HTML 转义（例如不碰反引号、不处理未配对代理对）；它服务的是"拼装层自己产出的文本与属性"，这个范围够用，但别把它当成通用的消毒函数。

## Testing

`frontend-next/tools/mhtml-roundtrip.mjs` 第 7.2 节（本轮新增，该脚本由 `npm run check` 串起）直接调 `buildSummary()` 与 `buildSnapshotDocument()`：

- 夹具的 `source` / `query` **刻意带 `&`、`'`、`<`**（标题由 `source` 派生，所以一并覆盖；干净夹具测不出这类缺陷），断言 `<title>` 里是 `AT&amp;T &amp; &lt;op&gt; &#39;x&#39;`、全篇没有 `&amp;amp;`、单引号不以裸 `'x'` 出现、筛选词里的 `<b>` 没有逃逸成真元素、摘要里的来源与标题同源同一次转义。
- 另有一份"敌意"摘要（`total: "2<script>"`、`shown: "<b>1</b>"`、`success: "x&y"`），断言统计/视图数字只以实体形式出现。

三处各自做过**变异验证**（在 scratch 的仓库副本上把写法改回旧形态，再跑 `node frontend-next/tools/mhtml-roundtrip.mjs`）：

| 变异 | 结果 |
| `sourceTag` 改回 `escapeHtml(realSource)`（双转义回归） | 3 条断言失败（标题、单引号、摘要来源） |
| 删掉 `escapeHtml()` 里 `'` 那一行 | 3 条断言失败（同上） |
| `statsHtml` / `countHtml` 的数字改回裸拼 | 1 条断言失败（"统计数字全部走转义"） |

未验证（如实记）：断言只覆盖到拼装层的字符串产物，没有在真实浏览器里核对该标题在文件管理器/标签页里的渲染（浏览器对 `&#39;` 之类实体的处理是标准行为，不是本改动引入的不确定性），也没有给"上游传了非数字"这条路径加真正的运行时夹具（它只由上面那份敌意摘要覆盖）。
