# Agent Note: 新前端「归属地」列只写国家，场景缺项统一显示 -1

Status: implemented

## Problem

[十列宽表](2026-09-22-frontend-single-view-redesign.md) 落到真实数据上之后，有两处**显示契约**在真实形态下说不通：

1. **「国家 / 地区」列把同一个词写两遍。** 这一列的内容是「国家 · 城市」，但后端的 `location` 串在真实产物里大量是 `Hong Kong Hong Kong`、`Singapore Singapore` 这种国家与城市同名的形态（本轮 25 节点真扫里有 3 条是 `Singapore Singapore`，另有多条 `Hong Kong Hong Kong`）。这一列本来只有 116px，同名的城市吃掉其中一半，换来的信息量为零。
2. **缺项用一句「另有 N 项无数据」注记，代价写在布局上。** 那句话的长度随数据变化（`另有 1 项无数据` / `另有 3 项无数据`），把「IPure 场景评分」这一列的内容需求带着一起抖，列宽下限只能按最坏情况留（358px）。更麻烦的是缺一项时这一行的六个 chip 变成五个：把两个节点的同一个场景横着比对，得先数位次才知道自己对的是哪一项。

两处都不是渲染 bug，是「有值/无值」怎么摆的选择，改了就是改**列契约**（表头文案、列宽、单元格结构、`data-label` 三处同源），所以记在这里。

## Decision

`app/render.js` + `app/records.js` + `styles.css` 三处的现行契约：

- **归属地只写国家**：`locationText()` 只返回 `result.country`（没有国家时按有没有出口 IP 退到「归属地未知」/「位置未知」）。表头文案由「国家 / 地区」改成「国家」。
- **这一列有 96px 的硬上限**：`.cell-geo` 补 `max-width: 0; overflow: hidden; text-overflow: ellipsis`（量法与 `.ident` 同一套）。不设上限时 96px 只是「期望宽度」，遇到更长的国名这一格会向表格算法多要宽度，被压的是「节点」列——那列本来就比内容窄 8px，再窄就开始吃状态药丸。裁掉的那截靠 `td.title` 读回全称，这也是这一列写 title 的唯一理由（不设上限时它恒等于 `textContent`，是死代码）。≤900px 卡片模式必须撤销这条（block 布局里 `max-width:0` 会把国名裁成 0 宽），与 `.ident` 一起写在同一个 media block 里。
- **有出口 IP 的行，场景恒为六个 chip**：上游没返回值的项（`null` / 缺键 / 域外值）一律显示 `-1`，与上游明确回 `-1` 的「该地区受限」共用同一个中性灰通道，同样不参与数值排序。
- **两种 `-1` 的成因只能在 `title` 里区分**，格子里永远只有一个数字：上游没返回值 → `「AI：无数据（显示为 -1）」`；上游真值就是 `-1` → `「AI：该地区受限」`；正常分数 → `「AI 场景评分 82」`。把没测说成「受限」是撒谎，把受限说成「无数据」是抹掉事实，两者都不许。
- **IPure 取值先过域，再谈显示**：`ipureValue()` 要求**整数**且落在 `-1`（受限哨兵）或 `0..100` 内，其余（`-1.4`、`-0.5`、`-2`、`101`、非数）一律当无值。只用 `integer()` 的截断会造出两条假话：`-1.4 → -1` 把「上游回了域外值」说成「该地区受限」，`-0.5 → 0` 凭空造出一个 0 分。六项场景与总分（`score`）走同一个函数。
- **`scenarioScoresOf()` 不再把「六项全空」折叠成 `null`**：上游给了评分对象就一律返回六项（缺项为 `null`，交给渲染器显示 `-1`）。只有上游根本没这个键（不是对象 / 是数组）时才是 `null`。
- **「无场景评分」只属于没有出口 IP 的行**：判据是 `result.exit_ip`，不是「有没有评分对象」——否则上游某次漏发 `ipure_scores` 时，连上的行会静默退化成另一句文案，而这一列的长度契约就靠「连上的行恒六格」撑着。没有出口 IP 的行另外五列已换成 `colspan=5` 的失败原因，两者同源同退，表格列数恒为 10。

列宽跟着重测（`COLUMNS` 仍是唯一真值，量法见 proposed 笔记者）：

| 位置 | 原 | 现 | 依据 |
|---|---|---|---|
| `geo` 列宽（`COLUMNS`） | 116px | 96px | 62 行真实+示例数据里最长的国家 `United States`，含左右内边距实测 83.94px，留 12px 余量 |
| `.grid .cell-scn` 下限（CSS 唯一一条列宽） | 358px | 346px | 最宽的一行六个 chip 合计实测 326px + 18px 内边距 + 2px 余量 |
| `.grid { min-width }` | 1354px | 1322px | 上述两项各减 20px / 12px；也和 9 个显式列宽之和 976 + 场景列下限 346 **逐像素相等**，不是估计值 |

1440 视口下 `.shell`（`max-width:1400px; padding:0 20px`）减去 `.table-wrap` 的 1px 边框给出 1358px，与 1322 的差值 36px 现在是**真的余量**：`geo` 有了 96px 硬上限之后，国名再长也不会来吃这 36px（此前它只是「期望宽度」，会挤压节点列）。

## Testing

- **真实订阅闭环（同进程 API + 静态站 + 真扫）**：`POST /api/scans` 真扫 25 节点（本轮 44.4s，分布 10/4/11），`?job=` 深链进真实 Chromium，**42/42 断言通过**。针对本轮改动的断言包括：表头 10 列且第 4 列表头恰为「国家」；`geo` 单元格文本逐行等于 `requests.lookup.data.country`（等于就证明没有再把城市拼进来）；有出口 IP 的行 `scnVals.length === 6`；**逐项**核对场景值与 export 一致，并按「上游是否真没返回值」分别要求 `title` 说「无数据」或说「该地区受限」；`.scn-none` 只允许出现在没有出口 IP 的行上；「另有 N 项无数据」彻底绝迹；**国家列没有被裁断的国名**（逐格比 `scrollWidth` 与 `clientWidth`）；**导出按钮在有数据时保留 `index.html` 的说明文案**，坏深链时换成禁用原因。
- **取值域收敛是 Node 侧直调 `toRows()` 试的边界**（不靠浏览器）：`-0.5` / `-1.4` / `-2` / `101` / 总分 `120` 全部落成无值，`-1` / `0` / `100` 原样透传。这条断言在修复前是红的（`-1.4` 出来是 `-1`、`-0.5` 出来是 `0`），不是补的橡皮图章。
- **示例数据两条成因都走到了**：`data.js` 里 `洛杉矶 ColoCrossing-03` 的 `ecommerce: -1`（上游真值）与 `email: null`（缺项）同现，实测 tooltip 分别是「电商：该地区受限」「邮件：无数据（显示为 -1）」；示例路径 12 行、表头含「国家」、六格恒定、1440 无横滚、对比度 0 违规，全部保持。
- **规格文件与列宽是量出来的**：交付的 `.mhtml` 里 `<td class="cell-geo" data-label="国家" title="United States">United States</td>`、`<li class="scn" data-ipure-score="-1" title="AI：该地区受限">`；产物 25 行、表头 10 列、无订阅 URL、零外链，内嵌 CSS 与仓库 `styles.css` 行尾归一后逐字符一致（产物部件按 MIME 惯例用 CRLF，仓库文件是 LF，差的 629 字节就是行尾）。

## Alternatives considered

### Why not 保留「国家 · 城市」，只在同名时去重（`Hong Kong` 只写一次）？

最强理由：不丢信息。城市是除国家外唯一能区分同国多节点的字段，「新加坡 · 新加坡」去重后仍是「新加坡」，但「美国 · 洛杉矶」能保留「洛杉矶」，比只写国家更有用。否掉的原因是它留下一条**按数据形态分岔**的显示规则：同名去重、不同名保留，同一个列在同一张表里就有两种排版，横向比对时每行的信息量还不一样——而这列只有 116px，正是被「有时两个词、有时一个词」逼到要按最坏情况留宽。城市没有丢：它仍在检索索引里（`main.js` 的 `buildSearchIndex` 收 `result.city`），搜「洛杉矶」照样命中。

### Why not 缺项保留「另有 N 项无数据」，只给它一个固定的槽位（比如恒定 92px）？

最强理由：缺项必须说出来，否则「只有 4 项」会被读成「这 4 项就是全部」——这是原设计写这句注记的初衷，而且它比 `-1` 更不容易被误读成受限。否掉的原因是固定槽位并没有解决根因：六格变五格之后，**同一行的第 5 个 chip 有时是 `email`、有时是 `ecommerce`**，而这一列的全部价值就是横向比对同一项；这跟注记占多宽无关。

### Why not 缺项留空（不画格子也不显示 -1）？

最强理由：空着最诚实——没测到的东西就不该出现数字，`-1` 与「受限」同形，画出来必然有人当成低分。否掉的原因是留空在表格里读起来像渲染失败，而且它把「这一行只测了 4 项」这件事实藏进留白里，只有鼠标悬停才知道有缺项。用中性灰的 `-1` + `title` 说明，是「一定看得见、且不会被当成分数」的那条路。

## Consequences

- **收益**：列宽省下 32px（geo 20 + 场景列 12），场景列从「按最坏情况留宽」变成恒定六格——同一项在每行的位次固定，横向比对不用数位次，列宽也再不会被注记长度带着抖。
- **代价**：`-1` 在一屏里出现两种含义（没测到 / 该地区受限），只能靠 `title` 区分；`-1` 的观感天生像「异常值」，读表的人若不看 tooltip 会把缺项读成受限。这条已写进渲染器注释，避免后来者只改数字不改 tooltip。
- **代价**：城市不再一屏可见，只有搜索能到（搜索索引仍收 `city`）。
- **真实数据的覆盖实情**：本轮真扫**抽到了**上游真值 `-1`（3 条记录的 `ai` 项），此前笔记里「真实产物从未出现 -1 哨兵」的判断是错的，已改；而「上游没返回值」在真实数据里只与失败行同时出现（60 个缺项全部来自 10 个失败行的 6 项），**连上的行缺项**这条路径仍只有合成数据覆盖。
