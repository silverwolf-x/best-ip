# Agent Note: 窄屏卡片改成流式自适应——只留一个断点当模式开关，卡片内部不再有轨道数

Status: implemented

## Problem

窄屏那一版「一行一节点」的卡片，是把"数据正好长这样"当成了契约：

- 卡片内部写死 `grid-template-columns: 26px 1fr auto auto` 四个轨道，再在 `@media (max-width: 620px)` 里补一刀把两个分数胶囊堆叠起来。轨道数、每一档该堆哪一格，全是手算的特例；视口落在没写到的宽度区间（例如 700px）就没人管过。
- 卡片里的字段标签靠 `td[data-label]::before` 自报家门，同一个 DOM 在两种模式下走两套样式路径。
- 实测这一版在 375px 下每张卡片 377px 高，一屏只看得到两张；节点名或 ISP 名一长，相邻两格会被压在一起。

另一件同样重要的事：**"无横向溢出、文本两两不重叠、九个字段不裁切"从来没被机器检验过**。当时的判据是"看着还行"，所以既说不清它什么时候是对的，也说不清它什么时候开始坏的。

## Decision

整份样式仍然只有一个断点（900px），但它现在只是一个**模式开关**：≥901px 是十列宽表，≤900px 是「一行一节点」。卡片内部没有任何轨道数：

- `.grid .row { display: flex; flex-wrap: wrap; }`：排不下就换行。`.grid .row > td { min-width: 0; overflow-wrap: anywhere; }`：长内容肯折行而不是顶到邻居身上。宽度连续变化时不存在"轨道数不对"这种失效形态——flex 换行走的是正常流，正常流里两个块不会叠在一起。
- 视觉次序用 `order` 重排（两个总分提到节点名后面），DOM 顺序不动：导出与快照读的是 DOM 顺序。
- 页面留白、卡片横向间距和节点字号用 `clamp()` 连续缩放；卡片纵向留白保持紧凑。`@media (max-width: 620px)` 及 `data-label::before` 标签生成已删除。
- 卡片态的表头**不是** `display: none`（那会把十个列名从可访问性树里一起删掉），而是复用同文件 `.sr-only` 的 1px clip-rect 盒：仍在 DOM 里、仍进无障碍树、零像素。
- 节点名在卡片态不裁（桌面那套 `nowrap + 省略号` 会把名字咬掉），因为卡片里"折一行"是免费的：`.ident .node { white-space: normal; overflow-wrap: anywhere; }`。
- 首行保留排名、节点和两项总分。节点的 flex basis 从可用宽度扣除 `--rank-width`、两个 `--score-width` 和三个 `--card-gap`，其余空间全部给名称；网络字段从下一行自然排布。尺寸变量与组件共用，避免固定百分比让 IP 在平板宽度挤入首行。
- 手机搜索占整行，状态、排序与导出控件按 flex basis 换行并填满余量；不增加宽度断点。总分字号为 16px，场景标签为 10.5px；服务商与纯文本 AS 各占一行。卡片使用细边框、轻阴影，hover 不产生位移。

十条列的宽度预算、`COLUMNS` 单一真值、`.mhtml`/`.html` 导出、`colspan=5` 失败行形态都没有动，见 [新前端改成单视图十列宽表](2026-09-22-frontend-single-view-redesign.md)。

## 行高一致靠结构，不靠魔法数字

窄屏之外的桌面宽表也有两条"高度要靠结构算出来"的规则：

- **失败行与数据行同高**：不是给 `.cell-absent` 写死 `height: 51px`，而是给节点格的第二行（`.ident .ident-sub`）一个 `min-height: 19px`（等于状态药丸的高度）。状态药丸在不在、节点名一行还是两行，都由内容决定，行与行之间不再差 3px。
- **末行不矮 1px**：末行的分隔线改成 `border-bottom-color: transparent`，而不是 `border-bottom: 0`——1px 照旧占位，视觉上等同于没有这条线，但行高不再单独少 1px。
- **`.ident { min-width: 200px }`**：桌面表格是 `table-layout: auto`，只有 `max-width: 0` 时，邻居列里一段不可断的长内容（实测是一个长 ISP 名）能把这一列从 268px 一路挤到 82px，节点名、协议、状态药丸一起溢出到出口 IP 列上。给了下限之后同样输入实测 `ident=200`、零重叠、行高仍统一 55.5px。

## Alternatives considered

- **保留分断点的卡片网格，再多写两三个断点** — 最强理由：每一档都是一个可以静态读懂的布局，出问题时"这一档长什么样"一眼可证，也不需要 flex 换行这种"运行时才知道结果"的机制。否掉的原因：断点只覆盖写下来的那几档，而实测这套写法的失效形态（相邻两格文字压在一起、页面横向溢出 5px）恰好出现在没写到的宽度和长内容上；再加三个断点只是把"没人管过的区间"变窄，不是消除它。
- **把桌面宽表改成 `table-layout: fixed`** — 最强理由：列宽由 `colgroup` 定死，任何长内容都只能在自己格子里处理，从根上不可能挤压邻居列，连 `.ident` 的下限都不需要。否掉的原因：实测它把长 ISP 那几行撑到 106.25px（其余行 55.5px），直接违反"数据行行高一致"；而它要动的是桌面十列密度的地基，而它想解决的极端长内容问题已经由 `.ident` 下限这条小改动拿到了。
- **保留 `.cell-absent { height: 51px }` 这条下限** — 最强理由：它是量出来的（真实产物 25 行里 9–11 行失败，不给下限会塌到 37px），而且只影响失败行、改一处就够。否掉的原因：51px 是"节点列恰好两行"的乘积，节点名一旦折行或被省略号处理，这个数就不再等于"和数据行一样高"；换到 `.ident-sub { min-height: 19px }` 之后，同高关系由结构保证，与内容无关。

## Consequences

- **收益与代价**：早期卡片实测高 377px。最终样例在五个规定窄屏宽度下为 142.38–169.5px；总分、场景文字放大且 AS 独立成行，比上一轮 140.38–160px 略高。320px 的长名称样例可到 218.2px，优先完整显示内容，每屏数量取决于视口高度与顶部控件占用。
- **收益**：八个规定宽度上"页面横向溢出 / 文本两两重叠 / 核心字段裁切"全部为 0，另加十二个额外宽度同样为 0；并且在故意灌入敌意数据之后，窄屏 320–900 仍然是 0 违规。
- **收益**：`620px` 断点与 `data-label::before` 一起消失，卡片态与表格态共用同一份单元格 DOM；行高一致不再依赖 `height: 51px` 那种与内容绑定的常数。
- **代价与已知上限**：卡片态表头只活在无障碍树里（视觉上看不见是刻意的）。**列宽预算一旦刷新，必须重新量这两件事**：`.ident` 的省略号预算，以及卡片态的换行行为。
- **代价与已知上限**：桌面仍是 `table-layout: auto`，一段不可断的超长内容（例如 39 字符的 IPv6 出口 IP）仍会让浏览器重新分配列宽；当前压力样例没有文字重叠，超长节点名会显示省略号，并保留 `title`。`table-layout: fixed` 的实验有行高不一致问题，未采用。
- **已知上限**：卡片态刻意不裁节点名，代价是极长的节点名会把卡片撑高——这正是"高度由内容决定"想要的行为，不是缺陷。

## Verification

- 测量器：会话临时目录里的 `measure.js`（未入库）在真实 Chromium 里以"精确宽度的同源 iframe"逐档测量，并自己给出 violations：页面溢出 / 可见文本两两重叠 / 核心字段（九项）裁切与不可见 / 卡片子元素越界 / 宽表行高是否唯一。
- 八个规定宽度（375 / 414 / 620 / 768 / 900 / 1024 / 1280 / 1440）：页面溢出 0px、重叠 0 处、裁切 0 处；1024/1280/1440 行高统一 55.5px，1440 时 `.table-wrap` 为 1390/1390（不滚），1024/1280 只有容器自身滚（1322/974、1322/1230）。
- 额外十二档（320 / 360 / 480 / 500 / 560 / 700 / 860 / 950 / 1100 / 1200 / 1360 / 1600）同样 0 违规。
- 最终压力样例为 72 字符无空格节点名、39 字符 IPv6、长 ISP 和长 AS；320–900px 下仍 0 违规，卡片高 143.13–313.2px。桌面重叠与页面溢出为 0，行高统一 55.5px，但测量器报告 12 个超长节点名裁切；这是桌面既有省略号行为，不计为完整显示通过。
- 早期压力对照（68 字符节点名等输入，先于最终视觉打磨）：当时 HEAD 在 375px 出现页面横向溢出 5px、17 处重叠；1024/1440 各测得 56 处重叠以及三种行高（50.5 / 52.63 / 53.63）。该组为历史定位证据，最终样式与压力样例的结果以上述最终复测为准。
- `npm run check`（含前端契约 a–d 与 `.mhtml` 往返）、`npm run verify-notes` 全绿。
- 同批恢复工作区编辑时丢失的 CSS 选择器前导，因果对照及检测上限见 [CSS 规则前导修复](../bug-fix/2026-09-28-css-qualified-rule-lost-preclude.md)。
